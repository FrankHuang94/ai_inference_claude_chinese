## 这份数据库解决什么问题

AI 推理的公开资料有三个结构性缺陷。

第一是**口径混乱**。同一个 "TTFT" 在两份 benchmark 里可能相差一个完整的排队时延；同一个"吞吐"可能是 output token/s，也可能把输入 token 一起算进去。不统一口径就比较数字，得到的结论往往是错的。

第二是**层次割裂**。谈 KV cache 的文章不谈 HBM 带宽，谈光互连的文章不谈它服务的是 all-to-all 还是 KV 迁移。而真实的推理系统里，一个 P99 时延问题的根因可能在调度器，也可能在 NIC 的 incast，也可能在机架的功率封顶。

第三是**事实与推测混写**。厂商宣称、第三方拆解、媒体转述和匿名爆料被平铺在同一段文字里，读者无从判断哪一句可以拿去做决策。

本数据库针对这三点做了三件事：**统一口径**（[GLOSSARY](../../GLOSSARY.md) 末尾的单位规范 + 每篇文档的"关键术语"表）、**贯通层次**（18 个模块按端到端栈组织，交叉链接而非重复叙述）、**标注来源等级**（每条事实性陈述携带 7 档披露标签之一）。

## 三种读法

### 读法一：按问题检索

你有一个具体问题——"P99 高但均值正常"、"要不要上投机解码"、"这块卡够不够跑 128K 上下文"。

直接去 [INDEX 的快速路径](../../INDEX.md#5-快速路径)。它给出的是**阅读顺序**而非单篇文档，因为这类问题的答案通常横跨 2–3 个模块。

### 读法二：按层学习

你要系统补齐某一层的知识——serving 层、编译器层、网络层。

去 [INDEX 的按系统层检索](../../INDEX.md#2-按系统层检索)，然后从对应模块的 README 开始，它给出了该模块内部的阅读顺序与前置依赖。

### 读法三：按角色贯通

- **推理工程师**：00 → 01 → 02 → 03 → 04 → 05
- **基础设施/硬件**：00 → 01 → 07 → 08 → 09 → 06
- **技术战略/投资**：00 → 01 → 14 → 15 → 16
- **面试准备**：00 → [17](../17_interview_prep/) 的 90 天计划

## 必须理解的三个约定

### 约定一：披露等级

任何涉及规格、性能、成本、市场、客户的陈述，都携带以下标签之一：

| 标签 | 含义 | 可以用来做什么 |
|---|---|---|
| `官方披露` | 厂商/机构官方渠道直接陈述 | 可作为决策依据，但注意厂商选择性披露 |
| `技术文档披露` | 官方技术手册、白皮书中的规格 | 同上，通常比市场材料更可靠 |
| `开源代码/配置披露` | 可在公开 repo 中直接验证 | 可核实性最高的一类 |
| `独立可复现实验` | 有完整环境说明、第三方可复现 | 跨厂商比较的最佳依据 |
| `可信第三方估计` | 有方法论说明的第三方研究 | **不等于**事实，可用于建立量级感 |
| `未公开` | 厂商未公开该项 | 提醒你：这里的空白是真实的，不要用常识补 |
| `待核实` | 有线索但未找到一手来源 | 待办事项，不可引用 |

**最常见的错误是把"可信第三方估计"当成"官方披露"来引用。** 本库在结构上强制区分二者。

### 约定二：数字必须带口径

本库中每个性能数字都应回答：什么模型、什么硬件、什么软件版本、什么量化、什么输入输出长度、什么并发、什么分位数。缺任何一项，该数字都不可跨来源比较——这一点在 [如何读 benchmark](03_how_to_read_inference_benchmarks.md) 中展开。

### 约定三：公式是近似模型

本库大量使用性能与成本公式。它们的价值在于**给出量级和敏感度**，不在于给出精确答案。所有公式都会显式声明假设与不适用范围。看到 `$0.0037421/1K tokens` 这样的数字请立刻警惕——它的有效位数远超输入数据的精度。

## 结构导航

```text
inference-atlas/
├── INDEX.md          ← 全库唯一入口，从这里开始
├── GLOSSARY.md       ← 术语与单位规范
├── AGENTS.md         ← 构建协议（单一 Agent、串行、模块化）
├── docs/00..17/      ← 18 个内容模块
├── data/*.csv        ← 结构化数据（GitHub 会渲染为可排序表格）
├── data/schemas/     ← 每个 CSV 的字段定义与录入纪律
├── templates/        ← 写作模板
└── scripts/          ← 13 个 QA 脚本
```

**文档正文与结构化数据的分工**：文档负责解释"为什么"和"怎么权衡"，CSV 负责承载可排序、可筛选、可批量比较的事实。看到文档里提到某个加速器或论文，去对应 CSV 能拿到完整字段。

## 如何判断某段内容是否可信

本库不要求你信任它。每篇文档末尾都有"主要来源"表，给出可点击的一手链接。判断流程：

1. 这句话有披露标签吗？没有 → 视为本库推论，自行判断；
2. 标签是 `官方披露` 还是 `可信第三方估计`？后者不能当事实用；
3. 点开来源链接，确认它确实说了这句话；
4. 看"最后核验"日期，超过复核周期的高时效内容可能已过时。

如果你发现事实错误、失效链接或口径不一致，**事实性纠错优先于新增内容**——提交方式见 [CONTRIBUTING](../../CONTRIBUTING.md) 第 7 节。

## 本库的已知局限

诚实地列出来，比让你自己踩坑好：

| 局限 | 说明 |
|---|---|
| 闭源系统的内部细节大量 `未公开` | 主要模型公司的推理基础设施细节极少公开，本库不猜测 |
| benchmark 覆盖有限 | 只收录条件完整、可判断可比性的结果，因此数量远少于网络上流传的对比图 |
| 高时效内容会过时 | 定价、路线图、财报的复核周期为 90–180 天，请核对日期 |
| 不含私有或受限材料 | 不收录 NDA 材料、泄露文档、未公开路线图 |
| 不构成投资建议 | 模块 15 提供的是尽调**框架**，不是结论 |
